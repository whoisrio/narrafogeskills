# 像素主题目录

机器读的真相源是 `kit/themes.ts`（`PIXEL_THEMES`），本文件是人读索引。色值只在一处维护，两边不要各写一份。

## 三套主题

| id | 调性一句话 | 适合 | 慎用 |
| --- | --- | --- | --- |
| `pico8` | PICO-8 16 色，蓝紫底 + 黄强调，机器味最正 | 技术、代码、系统内部、协议、复古计算 | 需要温和、生活化的题材 |
| `cga` | IBM CGA 16 色，四色硬对撞，最"80 年代 PC" | 硬件、老式界面、复古游戏、极硬的技术断言 | 长时间讲述（高饱和容易累） |
| `db16` | DawnBringer 16，低饱和偏土，档案感 | 档案、复盘、长片讲述、需要克制的场合 | 想要"发光屏"科技感的题材 |

默认 `pico8`。brief 没写 themeRef 时用它。

## 每套主题提供什么

一个主题就是一组语义键到色值的映射，组件只认键名：

- 底与面：`bg` / `bgDeep` / `panel`
- 线与边：`line` / `lineHi` / `edge`
- 文字阶：`soot`（暗）/ `ash`（中）/ `bone`（亮，正文与字幕）
- 主强调：`accent`
- 语义色：`code` / `data` / `os` / `protect` / `agent` / `evidence` / `unknown`

语义色是给"概念"用的，一旦定下就全片不换。同一个概念第三次出现时还是同一个色，观众靠这个认人。

## 主题解析规则

1. brief 里写 `themeRef: pico8 + pixel`，explainer 用 `themeById('pico8')` 取主题，包进 `PixelThemeProvider`
2. brief 没写，用 `pico8`
3. 写了别的引擎的主题（比如 `playful`、`block-frame`），**不要硬套**：提示用户换像素主题，或者换引擎
4. 代码里不许出现十六进制色值。要做局部强调，用语义键或 `accent`，不要临时调一个新颜色

## 新增主题的准入

像素主题的色数封顶 20，全部不透明，明暗只有阶。所以新增一套主题不是"调一批好看的色"，而是**找一套已经成立的有限调色板**。

- 色值必须有出处：公开的像素调色板（PICO-8 / CGA / DB16 / NES / Sweetie 16 之类）、已有设计稿、或产品的品牌色收敛成阶
- 不许现场混色、不许用 alpha 造中间态
- 必须有至少三档文字色（暗/中/亮），否则字幕和辅助信息分不开
- 必须有至少四个语义色互不混淆，否则一章多概念就撞色
- 加完在 `kit/themes.ts` 与 master 的 `theme-catalog.json` 各登记一条，两边同步

## 和其他引擎主题的关系

doodle / sticker 的主题目录里没有像素主题，像素主题也不进它们的目录——引擎不通用，主题不通用。真要跨引擎复用同一套调性，做法是各自登记一条，色值分别从各自的可读性规则里取，而不是照搬。
