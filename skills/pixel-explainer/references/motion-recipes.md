# 动效配方（Motion Recipes）

像素风的动效不是"慢一档的平滑动画"，是另一套机制：**只在台阶上取值，台阶之间直接跳过去**。
本文件把导演给的出场方式词逐个翻译成这套机制，并且明确哪些词在本引擎里做不出来。

## 0. 三个原语

所有运动都由这三个函数生成，不要自己写插值。

```ts
import { staged, blink, typewriter } from '../kit'

// 台阶取值：给定 [帧, 值]，返回当前台阶，不做插值
const y = staged(frame, [[0, 60], [8, 56], [16, 52]])

// 硬闪：只有开/关
const on = blink(frame, 8)

// 打字机：每 hold 帧吐一个字
const text = typewriter(localFrame, 10, 1, '这一段话')
```

台阶的间隔就是"节奏"。间隔 2 帧 = 15fps 手感（最快但不糊），间隔 8~12 帧 = 明显的一步一顿，适合强调。同一段动画里不要混用三种以上间隔，否则像卡了。

## 1. 出场方式词表

导演（visual-brief）给的是风格无关的词。下表是像素引擎的落地方式：**能做的给出参数，做不了的给出替代，替代也必须保持语义**。

| brief 词 | 像素做法 | 参数 | 备注 |
| --- | --- | --- | --- |
| `pop` | 阶梯落位 + 1 帧高亮 | 位移 2 格 → 0，间隔 2 帧；落定帧整块换成高亮色 1 帧 | 这是默认出场。像素世界没有弹，只有"跳到位" |
| `slide` | 整格位移 | 每帧 4 格，末帧直接到 0 | 位移必须是整数格，绝不留 2.5 格 |
| `dissolve` | 抖点消融 | `ditheredIn(x, y, p)`，p 每 4 帧 +0.25 | 唯一允许的"变淡"手段 |
| `rush-in` | 大步长位移 | 每帧 8~12 格，落定帧不减速 | 不做 overshoot，回弹需要插值 |
| `typewriter` | `typewriter()` | 每字 1 帧（30 字/秒）；强调句可 2 帧一字 | 字幕与代码行首选 |
| `wipe` | 硬边揭示 | `clip-path: inset()` 的值取整数格，每帧推进 6~10 格 | 遮罩边缘必须落在格上 |
| `draw` | 线条生长 | `growWire(segs, distance)`，distance 每帧 +2 格 | 用来画流程、依赖、调用链 |
| `stagger` | 加速错峰 | 间隔 8 → 4 → 2 帧递减，收尾静止 0.5s | 等间隔会被读成机械复读 |
| `snap` | 错位落位 | 先落在目标位偏 2 格，2 帧后跳到目标位 | 磁吸感来自"跳"，不来自"滑" |
| `flip` | **做不了** | 换成"逐行揭示"（wipe 自上而下）或两帧硬切换图 | 翻转需要透视插值，像素风没有中间帧 |
| `blur-in` | **做不了** | 换成抖点阶梯显影：p 0.25 → 0.5 → 1 | 引擎禁模糊，没有降模糊这条路 |
| `scale-up` | 整数倍跳 | 1 → 2 → 3，每级停 2~4 帧 | 没有 1.37 倍。要么一格，要么两格 |
| `rotate-in` | **做不了** | 换成硬落位 + 1 帧白闪强调 | 旋转必然产生非整数边缘 |
| `shimmer` | **做不了** | 换成整块高亮 1 帧（`blink` 单次） | 扫光是渐变，渐变等于抗锯齿 |

遇到做不了的词，**不要勉强模仿**，用替代方案并保持导演原本的语义（是"强调"还是"切换"还是"揭示"）。做完在交付说明里点一句"这个词在本引擎换成 X"，别默默改掉。

## 2. 相机

相机是把场景内容包进一个父层，对父层做 transform。像素风的铁律：**父层的 scale 只能是整数，translate 只能是整数格**。整数倍下子元素的逻辑坐标乘整数仍是整数，栅格不会破。

| 镜头 | 做法 |
| --- | --- |
| 推近 / 拉远 | `scale` 在 1 / 2 / 3 之间跳，每次停 4~8 帧；不做连续缩放 |
| 横移 / 升降 | `translate` 每帧 4~6 格，落定取整 |
| 侧掠 | 内容自身整格 `translateX` 滑过固定取景框，取景框不动 |
| 视差 | 可以，但前景/背景只能整数倍速度差（1× / 2×），不做 1.3× |
| `whip` 甩镜 | 做不了连续甩，换成硬切 + 1 帧白闪 |
| `crash-zoom` | 1 → 3 → 5 三跳，每跳 2 帧，末帧停住 |
| `rack` 变焦 | 做不了（需要模拟景深/模糊），换成正片硬切 + 新场景首帧全亮一帧 |
| `orbit` / 3D | 本引擎不走 3D。导演标 `维度:3D` 的 Seg 直接退回，建议改分镜 |

## 3. 转场

默认硬切。像素风的转场预算很小，用多了像幻灯片切换器。

- **硬切**：不用做任何事，这是默认
- **1 帧白闪**：全屏 `Block` 填 `bone`，只出现 1 帧，用来切章
- **抖点消融**：全屏抖点 4~8 帧，用来切话题（比淡入干脆，又不生硬）
- **打字机重打**：新场景字幕从空开始，第一句重新打
- **不用淡入淡出**：两幅画面同时半透明，混出来的中间态颜色不在调色板里，一帧就破色数判据

跨场景衔接还有一条便宜的做法：上一场最后一个元素留在原位，下场第一个元素从它旁边 2 格处落位。视觉上像是同一次讲述还在继续，不像换了一页 PPT。

## 4. 时序

- 元素按阅读顺序逐个入场，相邻元素间隔 6~12 帧；纯装饰（扫描线、内框）不参与节奏
- 三层顺序：容器先（定义空间）→ 内容次（填数据）→ 标注最后（字与箭头）
- 节点先于连线：两端节点都落位，线才开始长
- 成组元素按行列交错，组内间隔 3~5 帧
- 批量同类元素（≥5 个格子/条目）用加速错峰，收尾必须静止 0.5 秒，让眼睛落地
- 已入场元素常驻不动，不呼吸、不浮动
- 超过 3 秒没有任何变化就是 PPT

## 5. anti-PPT：像素风最容易翻的车

方块、直线、静止画面，天生像流程图。这个引擎的 anti-PPT 不能靠"弹入"，只能靠**格子级的持续变化**：每 2 秒至少发生一次下列之一。

- 打字机推进一行字幕
- 阶梯线长出一节
- 一个字符格被点亮（换 `ash` → `bone`）
- 一块面板底色换一阶（`panel` → 下一阶）
- 一个括号从 4 角收拢到目标框
- 进度条推进 2 格

这些变化都不需要新元素进场，所以不会把画面搞乱，但让画面一直"在算"。

反过来，禁止用下列手段填空：

- 元素无意义地上下浮动
- 光标/扫描线整屏扫动（那是装饰性运动）
- 把同一句话拆成两屏

## 6. 确定性

代码里不许出现 `Date.now()` 与 `Math.random()`。伪随机一律固定种子（mulberry32 或哈希），seed 从元素 index 或 id 派生。抖点相位、散点位置、闪烁节拍全部要能逐帧复现，否则渲染到第 3000 帧会和预览不一样。

## 7. 字高与可读性

本引擎只有两档字号：60px（`t`）与 120px（`T`，多是章首问题）。

字幕就是 60px。别照搬可变字号引擎那条"辅助文字 ≥32px"——本引擎没有 32px 这一档，最小就是 60。层次靠颜色（`bone` / `ash` / `soot`）、位置（面板内/外）、边框来做，不靠字号递减。

两档字号带来的一个后果：**能上屏的字数被压得很死**。160 字/分钟的中文旁白，一行字幕大约 20~24 字，两行 40 字就是上限。写旁白时就按这个限制写，别指望排版压缩。
