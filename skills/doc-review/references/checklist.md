# 文档 Review 检查清单（通用）

适用于任意技术文档发布前的预检。每条按"看什么 / 怎么核实"组织，不绑定任何具体框架或项目。

## 一、事实准确性
- API / 方法 / 模式名称：对照官方文档是否一致
- 参数名、枚举值、版本号：是否准确，有无把旧版当现行
- 关键因果 / 依赖断言（"某功能需要某前提才触发"）：与官方描述是否一致
- 示例代码：能否对应官方示例，有无拼错的方法名 / 参数

## 二、内部一致性
- 同一概念全文是否同一写法（单复数、大小写、缩写）
- 前后段落是否互相矛盾（同一件事两种说法）
- 图表与正文是否对得上（图里的名字、顺序、字段与文字一致）

## 三、结构完整性
- 标题层级是否连续（无跳级），总标题是否存在
- 有无悬空引用（"见上图"但图不存在）、章节挂错层级
- 表格 / 列表是否完整（有无漏行、错列）

## 四、格式规范
- markdown 表格分隔与对齐
- 图表语法合法性（如时间线事件中文本含半角冒号会被当分隔符，需替换为其他符号）
- 重复字、空占位符、错别字

## 五、时效性
- 是否把"早期 beta / 实验性"当成稳定功能
- 涉及版本差异时，是否标注版本前提（如"旧版行为是 X，新版是 Y"）

## 六、核对依据记录
- 每条问题标注：核实来源（官方文档 / MCP / 源码）、官方原话或行号、置信度
