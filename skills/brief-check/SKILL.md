# Brief Check:实现 vs visual-brief 分镜的忠实度校验

explainer 实现完动画后,对照 visual-brief 的分镜 brief 逐项核对,保证实现忠实导演设计。

## 它与 frame-check 的分工

| | frame-check | 本 skill(brief-check) |
| --- | --- | --- |
| 查什么 | 布局(文字重叠/溢出/连线断裂/空白) | 内容(元素/动作/色码/时序/素材是否按 brief 做) |
| 输入 | 渲染视频 | brief 文件 + 渲染产物 + 实现代码 |
| 产出 | 布局问题报告 | 逐 Seg 忠实度匹配报告 |
| 时机 | 渲染后(可先于或后于本 skill) | 渲染后 |

两者互补:先 frame-check 确认"画得对",再 brief-check 确认"画的是 brief 要的"。

## 工作流

### 第 1 步:拿 brief

visual-brief 的分镜 brief(含场景/Seg 定义:实体→元件、动作类型、色码、cue 时间戳、音画偏移、素材路径)。可能来自:
- 用户提供 brief 文件路径
- explainer 实现时消费的那份 brief(同路径)

### 第 2 步:找实现产物

- 渲染产物:`out/` 下视频(或关键帧静帧)
- 实现代码:`src/` 下对应 Composition
- 确认能对上:brief 的 Seg ↔ 实现的场景/元素

### 第 3 步:逐 Seg 五项核对

对每个 Seg,对照 brief 与实现,查以下维度:

1. **元素完整性**:brief 标的实体→元件(如 api_block/version_tag/logo)在实现里都出现了吗?漏了哪个?
2. **动作匹配**:brief 标的动作类型(出现/高亮/否定/stamp/flow/对比)实现里对应了吗?(brief 说 stamp 否定,实现却是淡出 = 不匹配)
3. **色码贯穿**:brief 标的色码(如"一代=灰蓝、二代=青绿")实现里同一概念是否同色、没换色?
4. **时序与音画偏移**:brief 标的偏移(提前 0.3s/同步/滞后 0.2s)实现换算帧号对吗?(提前=-9帧/同步=0/滞后=+6帧,30fps)
5. **素材使用**:brief 标的 `public/xxx.png` 实现真的引用了,还是漏了/换了?
6. **出场方式匹配**:brief 标的 `出场方式`(pop/slide/dissolve/rush-in/typewriter/flip/wipe/stagger/blur-in/draw/scale-up/rotate-in/shimmer/snap)实现里对应了吗?(brief 说 rush-in 砸下,实现却是淡入 = 不匹配)同场景连续 3+ 相同出场且 brief 没要求 = 单调警告
7. **镜头语言匹配**:brief 标 `镜头` 的 Seg,实现是否用父 Group 变换(2D)或 Three.js 真实相机(3D)承接了范围变化?推近是否 ≤1.3x(超了位图会糊)?brief 标固定而实现却在推拉 = 不匹配
8. **表格动效匹配**:brief 标 `table` 的 Seg,实现是否用表格渲染(非硬堆卡片)?标的表格动效(逐行弹入/单元格高亮/列强调/行排序/数字跳动)做了吗?
9. **3D 维度匹配**:brief 对 Seg 标 `维度:3D(Three.js)` 的,实现是否真用 Three.js/r3f 渲染(点云/曲面/粒子流/3D柱/几何体morph/爆炸视图/3D节点图)?用 2D 冒充 3D = 不匹配
10. **物体无目的晃动**:已就位元素是否静止?有无入场后的无意义上下左右抖动/往复平移?(除非服务表达:错误 shake、情绪强调)有装饰性晃动 = 不匹配——这是视觉抖动,不看旁白也能判定

**判定标准**:不匹配 = brief 明确要求、实现没做到或做反了。**不是**挑风格差异——explainer 在画法上有自由度(只要满足 brief 的意图),那不算不匹配。但**新字段(出场方式/镜头/表格/3D)是导演显式指定的硬约束**,实现端不能自由发挥改掉(如 brief 要 rush-in 不能擅自改淡入),这是与"画法自由度"不同的地方。

### 第 4 步:产出报告

逐 Seg 输出,标清"哪个场景哪个 Seg 哪个元素 + 怎么不匹配":

```
# Brief Check 报告:<片名>

## 匹配摘要
- 通过:X/Y 个 Seg
- 不匹配:N 个 Seg(列表如下)

## 逐项
### 场景 1 Seg 2 [00:03.9-00:06.8]
- 元素完整性:✅ api_block/version_tag/logo 都在
- 动作匹配:⚠️ brief 标"api_block.pop",实现是 fade in(无 pop 回弹)
- 色码贯穿:✅ 灰蓝一致
- 时序/偏移:✅ 提前 0.3s 已按 -9 帧处理
- 素材:✅ public/logo/openai.png 已引用
- 出场方式:⚠️ brief 标 api_block 出场=rush-in,实现是默认 pop(单调,未按语义)
- 镜头:✅ 固定,实现无推拉
- 表格:➖ 本 Seg 无 table
- 3D:➖ 本 Seg 维度=2D
- 物体无目的晃动:✅ 落定后静止

### 场景 2 Seg 5 [00:08.0-00:12.5]
- 动作匹配:❌ brief 标"stamp + shake"(否定),实现只有灰色覆盖,无 ✗ 章
- 镜头:❌ brief 标 `镜头:拉远`(局部→整体),实现仍是固定框取,未见 Group 拉远
...
```

全部匹配也明确写"无问题"。

### 第 5 步:打回 or 放行

- 有不匹配 → 报给 explainer 修,修完重渲染再查
- 全部匹配 → 放行,进入最终交付

## 与 explainer 的衔接

- explainer 工作流第 5 步渲染自检后调用本 skill
- explainer 内部只做轻量自检(第 3 步一句"忠实导演概念?"),重校验交给本 skill
- 本 skill 只查不改——发现问题报给 explainer 修,不直接改实现

## 校验清单速记

- [ ] 每个 brief 标的元素都出现?(元素完整性)
- [ ] 每个动作类型都按 brief 做了?(动作匹配)
- [ ] 同概念同色,没换色?(色码贯穿)
- [ ] 音画偏移换算正确?(时序/偏移)
- [ ] brief 标的素材都引用了?(素材使用)
- [ ] brief 标的出场方式都按语义做了(无擅自改/无连续3+单调)?(出场方式)
- [ ] brief 标的镜头都承接了范围变化、推近≤1.3x?(镜头语言)
- [ ] brief 标的 table 用表格渲染+表格动效做了?(表格动效)
- [ ] brief 标 3D 的 Seg 真用 Three.js 渲染了?(3D 维度)
- [ ] 已就位元素静止,无无目的上下左右晃动?(物体无目的晃动)
