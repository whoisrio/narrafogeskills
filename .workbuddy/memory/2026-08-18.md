## frontend-slides 主题适配讨论（动画 skill 体系）

背景：想把 frontend-slides（opensource-refs 里，12 STYLE_PRESETS + 34 bold 模板）的配色/招牌母题用进动画 skill 链。现有 `style-context-templates.md` 是孤儿文件（无 skill 引用，intended 消费者 visual-brief-prompt.md 不存在）。

### 已确认的架构事实（ls 实测）
- `.agents/skills/` = runtime 真身；`.workbuddy/skills/` 下 doodle/frame-check/visual-brief 是 symlink 指向 `.agents`；`narraforgeskills/skills/` 是独立开发副本（非 symlink）。三份可能漂移，改代码必须同步 `.agents` 真身。
- visual-brief-design 无 references/ 目录，参考素材全部内联在 SKILL.md（动词→动作源表、容器库、焦点控制、布局规范、示例 1-6）。第 7 原则：风格无关、不写颜色/字体（L302）。
- doodle 引擎主题契约：BG/GRID/INK/PALETTE/ACCENT + lineConfig（描边 3px、roughness 0.5-0.8、圆角≥16）。

### 关键结论（经过用户反问收敛）
1. **"多 skill 跨目录共享读同一份主题文件"不可行**——装进 .agents 后 `../theme-catalog/` 相对路径断，且三份拷贝漂移放大孤儿坑。
2. **visual-brief 不负责选主题/配色**——它保持色盲导演：只输出抽象组件角色 + 可选 themeRef 元数据。配色由 explainer 渲染时 resolve。示例里的颜色标注应改为"由 explainer 从 theme 对象填"。
3. **主题目录 = 每个 explainer 自带副本**（各自 references/theme-catalog），single source 在开发侧维护 master 再同步副本；explainer 读自己目录里的文件，装到哪都解得开。
4. 借鉴 frontend-slides 的**架构**（目录化 + 主题选择步 + 配色/线条解耦 + 反 AI 味黑名单），非 34 个全搬。组件只能搬"招牌视觉母题"（金线 hairline/坐标纸网格/霓虹网格/L 角括号等），版面组件（hero/两栏）搬不了。

  - 定义：确认类 = 对旧知的肯定（"相信你已经会了"），不是转场词，不引新元素/转场，时长 2-4s。
  - 核心原则：已有元素做"肯定性"动效——不引新元素、不清场、不空屏。
  - 5 种套路按时长选：逐个确认（stagger 0.8-1s 打 ✓）/ 聚合收拢（scale 0.97）/ 角色反应（mascot 点头）/ 标记确认（✓ 已掌握标签）/ 焦点巡礼（元素间游走）。
  - 三个不能：确认≠清场（清场是下一个转场句的活）；确认≠引新元素；确认≠空屏。
- **例外清单钉死**：第 3 步"什么内容可以不配动效"明确确认类不在例外里（它有独立时长、必须配肯定性动效），归进"不配动效"是常见画崩来源。
